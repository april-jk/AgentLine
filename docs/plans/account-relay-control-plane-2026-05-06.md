# AgentLine 账号中转与用户管理网站方案（桌面端 + 移动端）

日期：2026-05-06  
状态：实施中（已落地后端第一版 API 骨架）

## 1. 目标

把当前“按 relay username 连接”的模式升级为“按账号管理设备并连接”：

1. 用户在网站注册/登录一个账号（邮箱+密码）。
2. 桌面端登录同一账号后，将本机注册为可控设备资源。
3. 移动端登录同一账号后，直接看到“在线的电脑资源列表”。
4. 移动端点击设备后，连接该设备对应会话并下发操作指令。

## 2. 架构拆分

### 2.1 数据平面（已有）
- Relay WebSocket 通道（`packages/relay`）
- AgentLine 桌面端后端常驻并注册到 relay
- 移动端通过 relay 与桌面端建立实时消息通道

### 2.2 控制平面（新增）
- 账号与会话：注册/登录/登出
- 设备目录：设备注册、心跳、在线态查询
- 中转门户网站：用户管理 + 设备管理 + 连接入口

## 3. 当前已落地（第一版）

在 `packages/relay` 已新增控制平面数据库与 API：

### 3.1 数据表
- `users`：账号
- `user_sessions`：登录会话（Bearer Token 哈希存储）
- `devices`：账号下设备目录（含 `relay_username`）

### 3.2 API（`/api/v1`）
- `POST /auth/register`：注册账号
- `POST /auth/login`：登录并返回 `accessToken`
- `POST /auth/logout`：登出
- `GET /me`：当前用户
- `POST /devices/register`：桌面/移动设备注册或更新
- `POST /devices/:deviceId/heartbeat`：设备心跳
- `GET /devices`：获取账号下设备及 relay 在线态（`offline|waiting|paired`）

## 4. 连接流程（目标形态）

### 4.1 桌面端上线
1. 用户在桌面端登录账号。
2. 桌面端调用 `POST /api/v1/devices/register` 注册设备，拿到 `relay_username`。
3. 桌面端后端用该 `relay_username` 维持 relay waiting 连接。
4. 桌面端周期心跳更新设备活跃状态。

### 4.2 移动端发现并连接
1. 用户在移动端登录同账号。
2. 移动端调用 `GET /api/v1/devices` 获取设备列表与在线状态。
3. 用户点击在线设备后，移动端使用对应 `relay_username` 发起 relay connect。
4. 成功配对后，进入会话控制页面（查看/切换/下发指令）。

## 5. 网站（Portal）页面规划

### 5.1 用户端
- 登录/注册页
- 设备列表页（在线状态、最后活跃、设备名）
- 设备详情页（会话入口、远程控制入口）
- 账号安全页（会话管理、退出其他设备）

### 5.2 管理端（后续）
- 用户总量、在线设备数、relay 健康度
- 异常连接追踪、风控封禁、审计日志

## 6. 安全策略

1. Token 不明文入库（仅存 SHA-256 哈希）
2. 密码使用 `scrypt` 盐化哈希
3. 全链路 `HTTPS/WSS`
4. 后续增加：
   - 登录/注册限流
   - 异地登录告警
   - 设备级授权（只读/可执行）
   - 2FA（可选）

## 7. 接下来两步（建议执行顺序）

1. **桌面端接入控制平面登录与设备注册**  
   桌面端启动后自动刷新 token + 注册设备 + 心跳。

2. **移动端接入设备列表与一键连接**  
   移动端登录后先拉设备目录，再通过 `relay_username` 建连。

---

这份方案保证了你要求的核心体验：  
“桌面端和手机端只要登录同一个账号，手机就能看到在线电脑资源，并控制对应会话。”
