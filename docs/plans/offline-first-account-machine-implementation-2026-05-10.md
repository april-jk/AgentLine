## L0 - 里程碑

### M1：离线直连基线稳定

目标：
- 未登录情况下，局域网直连稳定可用。
- 首次连接密码机制与本机信任机制落地。
- 主机访问密码基于现有 `RemoteAccessService` / SRP 能力演进。

退出标准：
1. 手机在离线状态下可扫描并连接桌面主机。
2. 首次连接必出密码校验。
3. 仅在用户选择“保存在本机”后，后续才允许免密。
4. 没有引入与现有 SRP 并行的第二套认证链路。

### M2：账号与机器目录（可选增强层）

目标：
- 在不影响 M1 的前提下接入账号和机器列表能力。

退出标准：
1. 桌面登录后可绑定/认领机器 owner。
2. 桌面心跳上报 LAN endpoint、relay endpoint、监听状态和过期时间。
3. 手机登录后可拉取机器列表并优先走未过期内网连接。
4. 控制面不可达时，M1 直连链路不受影响。

### M3：中继路径与主机密码策略统一

目标：
- 中继路径与直连路径使用同一套主机访问策略（首次密码，后续本机信任）。

退出标准：
1. 中继首次连接要求输入主机访问密码。
2. 中继复连可使用本地受信凭据免密。
3. 云端仍不保存访问密码。

### M4：加固与回归

目标：
- 建立直连/中继/登录/离线全矩阵回归，完成发布级验证。

退出标准：
1. E2E 矩阵通过率达到发布基线。
2. 扫描与连接体验问题（结果被历史覆盖、非法网段等）全部关闭。
3. 桌面端与移动端构建包可正常启动与连接。

## L1 - 工作流拆分

### WS1：桌面主机服务（`packages/server` + 桌面壳）

交付项：
1. 基于现有 `RemoteAccessService` 的主机访问密码模块（校验器、轮换、受信客户端管理）。
2. 直连认证接口（challenge/verify）。
3. 受信设备撤销接口与设置页入口。
4. 可选账号绑定与心跳上报能力（含 LAN endpoints）。
5. WebSocket 认证策略接入：非 loopback 直连和中继走统一主机访问认证。

完成定义：
1. 校验器与信任生命周期单测通过。
2. 手工冒烟覆盖：首次认证 -> 保存信任 -> 免密复连 -> 撤销后重认证。
3. 旧 relay password / direct password 语义已收敛为“主机访问密码”。

### WS2：移动端 RN（`packages/mobile-rn`）

交付项：
1. 连接源统一模型：扫描结果 + 账号机器 + 手动地址。
2. 路由引擎：内网优先，中继回退。
3. 首次密码输入与“仅本机保存”交互。
4. 本地安全存储凭据与失效处理。
5. 历史连接迁移到独立页面，不再覆盖实时扫描区。
6. 普通用户主路径改为机器候选列表；旧 relay username/password 表单仅作为高级调试入口。

完成定义：
1. 实时扫描结果始终优先展示在主列表。
2. 默认扫描主网卡 `/24`，禁止误扫 `127.0.0.0/24`。
3. WebView 页面内返回行为正确（先网页回退，不直接退出会话）。
4. 从账号机器列表点击机器时，不要求用户手动输入 relay username。

### WS3：控制面（`packages/relay` 控制 API）

交付项：
1. owner/机器绑定模型定稿。
2. 机器注册/认领/转移接口。
3. 心跳、端点健康、在线态字段完善。
4. `/api/v1/devices` 到 `/api/v2/machines` 的兼容/迁移层。
5. 兼容旧设备记录和旧 relay 标识。

完成定义：
1. API 合约测试通过。
2. 机器“单活 owner”约束在转移后仍成立。
3. v1 调用方在迁移期不被强制一次性改完。

### WS4：中继数据面（`packages/relay` 隧道）

交付项：
1. 复用现有 SRP 握手承载主机访问密码校验。
2. 新增受信凭据复连路径。
3. 统一错误码：需认证/认证失败/信任失效。
4. 如需新增消息类型，作为现有 SRP 状态机的语义别名，不绕开现有认证。

完成定义：
1. 中继链路具备与直连一致的安全语义。
2. 现有端到端加密隧道行为不回退。

### WS5：QA / 运维 / 发布

交付项：
1. 回归矩阵与故障处理手册。
2. 特性开关发布顺序。
3. 关键日志与链路指标（连接路径、认证失败、回退原因）。

完成定义：
1. 关键故障可在 UI 与日志中快速定位。
2. 发布说明包含迁移步骤与回滚策略。

## L2 - 分阶段执行细节

## Phase 0：基线保护

1. 先补齐/冻结当前行为测试：
- 直连连接、
- 中继连接、
- 扫描结果展示、
- WebView 返回行为。
2. 记录当前实现锚点：
- `RemoteAccessService` 的 SRP verifier 存储、
- `ws-auth-policy` 的连接认证策略、
- `/api/v1/devices` 的控制面接口、
- 移动端 `LoginScreen` 的旧 relay 表单入口。
3. 补充机器记录与旧 relay 记录 fixture。
4. 接入三类特性开关：
- `account_machine_registry_v2`
- `host_access_password_v2`
- `relay_host_auth_v2`

验收：
1. 特性开关全关时，主干行为与当前版本一致。

回滚：
1. 仅通过关闭开关回到旧链路，不依赖数据库回滚。

## Phase 1：桌面端主机密码核心能力

1. 梳理 `RemoteAccessService` 当前状态文件：
- 保留 SRP salt/verifier 作为主机访问密码校验器、
- 增加 schema version 迁移策略、
- 明确旧 relay username 只作为路由标识，不再作为用户理解的账号。
2. 建立/扩展本地安全存储结构：
- 密码校验器参数、
- 受信客户端清单、
- 密码轮换版本。
3. 实现 challenge/verify 语义：
- 优先复用当前 WebSocket SRP 握手、
- 仅当 REST 入口确有需要时再补 `/api/host/auth/*`。
4. 实现受信撤销与密码轮换。
5. 接入直连入口认证策略：
- loopback 可保持本地开发便利策略、
- 非 loopback 直连和中继统一要求主机访问认证。

验收：
1. 首连必输密码。
2. 已保存信任设备可免密复连。
3. 撤销后必须重新输入密码。
4. 现有 relay/SRP 连接路径仍可工作。

## Phase 2：移动端连接与扫描体验重构

1. 重构连接源模型：
- 实时扫描、
- 账号机器、
- 历史连接（独立页面）。
2. 实现连接路由引擎：
- 候选生成、
- 内网优先排序、
- 中继自动回退。
3. 接入认证交互：
- 密码输入、
- 是否本机保存、
- 失败重试策略。
4. 重构入口 UI：
- 首页优先展示机器候选和扫描结果、
- 历史连接进入独立页面、
- relay username/password 表单移入高级调试。
5. 加入扫描护栏：
- 默认当前网卡 `/24`、
- 禁止 loopback 默认扫描、
- 高级扫描为显式操作。

验收：
1. 主列表实时展示扫描结果，不被历史覆盖。
2. 非法网段输入给出可读错误，不进入扫描。
3. 页面返回行为符合预期，不误触发会话退出。
4. 账号机器列表点击连接时不展示 relay username/password 表单。

## Phase 3：账号机器目录（可选层）

1. 控制面机器模型定稿：
- `devices` 兼容旧表、
- `machines` 作为目标语义、
- 保留 relay username 旧字段，新增 machine route id/endpoint 字段。
2. 设计 `/api/v1/devices` 到 `/api/v2/machines` 的迁移：
- v1 继续服务现有桌面桥接和移动端、
- v2 返回 owner、endpoints、capabilities、heartbeat freshness、
- v1 可通过 adapter 透出必要 machine 字段。
3. 桌面端实现登录后机器认领/绑定与心跳：
- LAN IP、端口、绑定接口、
- `boundToAllInterfaces`、
- endpoint `lastSeenAt` / `expiresAt`、
- relay 在线状态。
4. 手机端拉取机器列表并与扫描结果融合。
5. 实现 owner 转移接口及桌面端确认流程。

验收：
1. 同账号可看到并连接已绑定机器。
2. owner 转移后保持“单活 owner”。
3. 控制面不可达时仍可离线直连。
4. LAN endpoint 过期后不被自动直连，只作为提示展示。
5. v1 旧调用方与 v2 新调用方在迁移期可并存。

## Phase 4：中继认证统一

1. 复用现有 SRP 握手作为中继首连认证：
- relay 继续只转发加密/认证握手消息、
- 桌面端继续作为密码校验权威。
2. 若需要新增语义消息，仅作为现有认证状态机的外层事件：
- `HOST_AUTH_REQUIRED`
- `HOST_AUTH_PROOF`
- `HOST_AUTH_OK`
- `HOST_AUTH_FAILED`
- `HOST_TRUST_REVOKED`
3. 中继路径复用桌面端认证服务。
4. 手机端接入中继密码校验与受信复连。
5. 完善超时、重试、错误提示与降级。

验收：
1. 中继首连必须密码。
2. 受信设备可中继免密复连。
3. 云端无密码托管痕迹。
4. 旧 relay username/password 普通入口已退出主流程。

## Phase 5：全量回归与发布

1. 执行回归矩阵：
- 离线直连未登录、
- 登录后内网优先、
- 中继回退、
- owner 转移、
- 密码轮换/撤销。
2. 跑全链路检查（lint/typecheck/tests）。
3. 构建桌面端与移动端发布包并做启动验证。
4. 输出发布说明、已知限制、回滚手册。

验收：
1. 无阻断级回归。
2. 构建包在目标设备上可启动并完成连接。

---

## 最小回归矩阵

1. 直连链路：
- 首连密码、
- 保存后免密复连、
- 撤销后重认证。

2. 中继链路：
- 首连密码、
- 受信复连、
- 中继不可达时直连仍可用。

3. 账号可选性：
- 未登录不影响直连可用性、
- 登录仅增强机器发现与快速连接。

4. 归属变更：
- 认领机器、
- 转移 owner、
- 旧 owner 失去账号列表快速连接能力。

5. 迁移兼容：
- `/api/v1/devices` 旧客户端仍可工作、
- `/api/v2/machines` 新客户端拿到 endpoints 与 owner 字段、
- 旧 relay username 记录能映射到 machine。

## 观测与诊断

1. 桌面日志：
- 监听地址与端口绑定结果、
- challenge/verify 认证结果、
- 受信凭据签发与撤销、
- 密码轮换与失效事件。

2. 手机日志：
- 扫描网段与命中数量、
- 路由选择原因、
- 认证弹窗触发原因、
- 直连/中继切换路径。

3. 控制面日志：
- 机器认领/转移审计、
- 心跳新鲜度、
- owner 冲突告警。
- endpoint 过期/更新事件。

## 风险与缓解

1. 风险：登录功能反向阻塞离线直连。
- 缓解：离线路径单独 E2E，作为发布阻断项。

2. 风险：受信凭据生命周期错误导致频繁重输密码。
- 缓解：对有效/撤销/轮换/过期状态建立专门测试集。

3. 风险：大网段扫描导致体验抖动。
- 缓解：默认 `/24`，高级扫描显式触发，提供进度和取消能力。

4. 风险：owner 转移认知不清。
- 缓解：桌面端强提示确认 + 控制面审计追踪。

---

## 本阶段不做

1. 云端密码找回或密码托管。
2. 多 owner 共享同一机器策略。
3. 离线签名票据体系（本次不引入）。
