# 统一规划：桌面执行端 + 移动控制端

日期：2026-05-06  
分支：`codex/mobile-desktop-control-architecture`

## 为什么要做这份规划

AgentLine 已经具备：

- 移动端适配的远程 UI（`packages/client`）
- 桌面应用壳（`packages/desktop`）
- 移动应用壳（`packages/mobile`）
- 安全远程链路（SRP + NaCl + relay）

因此这次不是推翻重做 UI，而是把现有能力整合成“独立桌面应用 + 独立移动应用”的完整产品形态。

## 产品目标

- 桌面端是本地安装的“采集器 + 执行器”，负责管理 provider（`code`、`claudecode`、`codex` 等）和本地资源。
- 移动端是安装式控制器，负责登录、会话管理、审批和执行监督。
- 用户可通过局域网直连或 relay，从手机安全访问并操控自己的电脑工作流。

## 架构基线

1. 桌面 Agent 运行层
- 代码基础：`packages/desktop` + `packages/server`
- 职责：
  - 本地进程与会话生命周期管理
  - Provider 适配与命令执行
  - 受策略约束的本地数据/文件访问
  - 推送与通知事件产出

2. 传输与安全平面
- 代码基础：`packages/server`、`packages/relay`、`packages/shared`
- 职责：
  - SRP 鉴权与会话续期
  - 端到端加密 WebSocket 载荷
  - 直连与 relay 两种连接路径
  - 多主机路由与重连行为治理

3. 移动控制端运行层
- 代码基础：`packages/mobile` + `packages/client` 的 remote 构建
- 职责：
  - iOS/Android 安装壳
  - 主机登录/切换、会话列表、会话控制
  - 工具审批与高风险动作确认
  - 基于 deep link 的快速连接

## 范围与非目标

本期范围：
- 独立桌面安装包和独立移动安装包
- 无账号体系下的“按主机凭据登录”
- 远程监督 coding session 和执行操作
- 面向远程控制动作的安全加固

本期非目标：
- 全量原生 UI 重写（保留 React 移动端 UI）
- 多租户组织能力
- 以完整桌面串流作为主交互模型

## 能力模型（手机端可做什么）

MVP 能力：
- 连接一台或多台个人桌面主机
- 启动/恢复/暂停/取消会话
- 发送 prompt、查看流式消息、审批/拒绝工具调用
- 触发预定义运维动作（测试/构建/重启/provider 安装）

二期能力：
- 受控文件浏览（读取/搜索/小文件下载）
- 白名单命令面板
- 主机健康遥测（provider 就绪、磁盘告警、agent 状态）

## 安全模型

- 默认强制 SRP 登录 + E2E 加密传输
- 增加操作风险分级：
  - 低风险：读取/列表类，无需额外确认
  - 中风险：写入类，一次确认
  - 高风险：shell/特权/破坏性操作，需二次认证 + 明确确认
- 桌面端增加本地策略配置：
  - 允许访问根目录范围
  - 允许命令族
  - 频率限制和审计保留窗口
- 审计事件不可变写入桌面数据目录

## 交付计划

### Phase 0：应用壳整合验证（1 周）

目标：验证独立应用打包链路稳定可用。

工作项：
- 验证 `packages/desktop` 在 macOS/Windows 的安装、启动、更新路径
- 验证 `packages/mobile` 在 iOS 模拟器和 Android 模拟器的安装运行
- 验证 deep link 登录从移动壳到远程登录流的通路
- 在移动端/桌面端设置页补一个统一“平台状态”诊断页

退出标准：
- 桌面应用可启动本地 server，并能被移动端访问
- 移动应用可完成登录、打开主机、恢复会话的端到端流程

### Phase 1：统一主机身份与控制契约（1-2 周）

目标：把主机归属和 API 契约显式化。

工作项：
- 将 `hostId` 升级为远程会话、元数据、URL 的一等标识
- 新增 `/api/host/status` 和 `/api/host/capabilities` 契约
- 持久化主机能力快照（provider 安装状态、远程访问启用状态）
- 让移动端主机选择页和主机详情页基于契约驱动

退出标准：
- 单一移动端二进制可稳定管理多台桌面主机
- 能力开关由数据驱动，不依赖硬编码 UI 假设

### Phase 2：远程执行控制层（2 周）

目标：让桌面端成为可被手机稳定驱动的执行器。

工作项：
- 增加受控操作端点：
  - provider 安装/检查
  - 重启/安全停止
  - 命令模板执行
- 所有操作携带风险等级元数据
- 移动端增加中/高风险确认流程

退出标准：
- 移动端可在不触碰桌面的前提下安全发起核心运维动作
- 所有高风险动作都有审计记录

### Phase 3：稳定性与可靠性加固（2 周）

目标：达到生产级的网络和设备抖动容错能力。

工作项：
- 强化睡眠唤醒、relay 波动下的重连/恢复
- 增加移动端离线动作队列（仅限非破坏性动作）
- 增加审批请求与操作失败的推送流
- 完善遥测与错误原因编码

退出标准：
- 常见移动端和网络中断场景下会话连续性可保持
- 操作者拿到可执行的失败原因，而非泛化报错

### Phase 4：发布与上线准备（1-2 周）

目标：双端产品可持续发布。

工作项：
- 安装包签名和发布流水线验证
- 移动端构建与发布流水线验证
- 安全清单、文档和 onboarding 更新
- 灰度与回滚策略文档化

退出标准：
- 桌面与移动产物可从 CI 稳定重复发布
- 支持文档覆盖安装、配对、恢复和安全模型

## 代码职责映射

- `packages/desktop`：安装体验、server 启动生命周期、本地控制入口
- `packages/mobile`：应用壳、deep link 流程、原生打包、移动运行时钩子
- `packages/client`：移动控制 UI、主机/会话/操作/审批
- `packages/server`：主机能力、操作控制 API、策略校验、审计日志
- `packages/shared`：主机/操作/风险等级共享契约
- `packages/relay`：远程 relay 路径的可靠性与可观测性

## 风险与缓解

- 风险：范围失控，演变成“全量原生重设计”  
  缓解：坚持复用现有 React 移动 UI，优先补能力闭环。

- 风险：远程操作扩张带来安全回退  
  缓解：风险分级强制执行 + 明确确认 + 全链路审计。

- 风险：多主机重连路径导致状态不一致  
  缓解：统一 `hostId` 主键与主机能力快照 API。

## 完成定义（DoD）

- 用户可独立安装桌面应用和移动应用
- 用户可在手机登录并安全控制桌面会话
- 高风险动作有门禁且可审计
- 核心会话控制和 provider 运维能力在移动端闭环
